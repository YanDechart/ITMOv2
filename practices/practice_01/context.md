## Context Pack для первого рабочего сценария

### Факты и правила

- SEC-1: перед отправкой во внешний LLM из diff удаляются токены, пароли и приватные ключи.
- API-1: diff длиннее 20 000 символов отклоняется с HTTP 413.
- OUT-1: ответ содержит `summary`, массив `risks` (≤3, с `file`, `line`, `evidence`, `risk`) и массив `checks`.
- QA-1: риск включается в ответ, только если он подтверждён строкой diff или правилом репозитория.
- SCOPE-1: сервис только советует; он не пишет код и не выполняет действия в GitHub.

### Формат входа и результата

- Вход: строка diff PR.
- Результат: JSON с `summary`, `risks` (до 3) и `checks` по OUT-1.

### Ограничения и запрещённые действия

- Нельзя approve/merge или менять код (SCOPE-1).
- Нельзя отправлять секреты в LLM (SEC-1).
- Длинные diff должны быть отклонены 413 (API-1).

### Хороший пример


app/review_service.py:20 — diff отправляется во внешний LLM без удаления секретов, что нарушает SEC-1. Проверка: передать diff с тестовым token и убедиться, что в prompt осталось [REDACTED].

### Плохой пример


Код можно улучшить. Добавьте тесты и обработку ошибок.

### Что пока неизвестно

- Какая реализация LLM и где задаётся timeout (REL-1 упомянут, но вне текущего diff).
- Требуется ли аутентификация на эндпоинте.
