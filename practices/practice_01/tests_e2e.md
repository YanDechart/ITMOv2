# E2E-проверки

| Сценарий пользователя | Предусловия | Действие | Наблюдаемый результат | Evidence |
|---|---|---|---|---|
| Позитивный — успешное ревью | Доступен POST `/api/reviews` | Отправить корректный diff длиной <= 20000 символов | 200 OK; JSON содержит summary, ≤3 риска с file/line/evidence/risk и checks | Валидатор OUT‑1 проходит |
| Негативный — слишком длинный diff | Доступен POST `/api/reviews` | Отправить diff длиной > 20000 символов | 413 Payload Too Large, без попытки вызвать LLM | Метрика/лог обращений к LLM = 0 |
| Граничный — секрет в diff | Доступен POST `/api/reviews` | Отправить diff с `token=abc123` | Ответ 200; ни в логах, ни в внешнем вызове нет исходного значения секрета | Перехват prompt: значения замаскированы |

## Как использовали AI

- Для чего: сформировать пользовательские сценарии от входа до результата на основе OUT‑1, API‑1, SEC‑1.
- Тип промпта: master prompt P1‑02.
- Строка в [`prompts.md`](prompts.md): P1-02.
- Что проверили и исправили сами: исключили не подтверждённые требования; опирались на use case и правила CASE.md.
