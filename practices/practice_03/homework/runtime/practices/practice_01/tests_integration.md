# Integration-проверки

| Связь компонентов | Что может сломаться | Как воспроизводим | Ожидаемый результат | Evidence |
|---|---|---|---|---|
| FastAPI ↔ ReviewService | Нет 413 при длинном diff (API-1) | POST `/api/reviews` с `diff` длиной 20001 | HTTP 413 без обращения к LLM | Логи тестового дублёра LLM пусты |
| ReviewService ↔ LLM | Секреты уходят в LLM (SEC-1) | diff содержит `token=abc123` | В запросе к LLM значение заменено на `[REDACTED]` | Перехват вызова LLM фиксирует редактированный prompt |
| API ↔ Парсер OUT-1 | Невалидная структура ответа | Нормальный diff, мокнутый ответ LLM | HTTP 200, JSON соответствует OUT‑1 (≤3 риска) | Схема/валидатор проходит |
| API ↔ LLM таймаут | Ошибка при таймауте внешней зависимости | LLM‑стаб зависает >10s | Возвращается контролируемый ответ по REL‑1 | Код ответа и формат тела уточняются; CASE.md не задаёт конкретный статус/формат (открытый вопрос) |

## Как использовали AI

- Для чего: сформировать интеграционные проверки API‑1, SEC‑1, OUT‑1 и поведение при таймауте по REL‑1 без выдумывания статуса/формата.
- Тип промпта: master prompt P1‑02.
- Строка в [`prompts.md`](prompts.md): P1-02.
- Что проверили и исправили сами: уточнили, что CASE.md не фиксирует статус/формат контролируемого ответа (открытый вопрос); сохранили проверки только по источникам.
