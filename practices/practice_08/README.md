# BugRadar — интерфейс сервиса поверх n8n

BugRadar помогает участнику команды быстро разобрать новое обращение для фиксированного репозитория `YanDechart/ITMOv2`. Пользователь вводит заголовок и описание, n8n вызывает AI-классификатор из практики 7.2, а интерфейс показывает тип, уверенность, приоритет и следующий шаг. Успешные анализы сохраняются в локальную историю.

## Основной сценарий

1. Пользователь заполняет два подписанных поля.
2. Клиент проверяет длину данных и блокирует повторную отправку.
3. POST-запрос уходит в webhook n8n.
4. n8n вызывает sub-workflow классификатора.
5. Пользователь видит реальный результат и новую запись в истории.

Интерфейс также показывает пустое состояние, загрузку, ошибку с повтором и адаптивную мобильную версию.

## Стек и библиотека компонентов

- React + TypeScript + Vite;
- **Material UI**: Button, TextField, Card, Chip, Dialog, Alert, Skeleton и LinearProgress;
- общая MUI-тема в `src/theme.ts` задаёт цвета, типографику, радиусы, отступы и focus-ring;
- Vitest + Testing Library + MSW для клиентских тестов.

Визуальная структура вдохновлена my.itmo, а цветовая гамма — обложкой The New Division: `#090909`, `#E9E7DD`, `#00A8E8`, `#D1122F`.

## Установка и запуск

Требуется Node.js 20 или новее.

```bash
npm install
cp .env.example .env
npm run dev
```

В `.env` укажите production URL опубликованного webhook:

```env
VITE_N8N_WEBHOOK_URL=https://n8n-itmo.cyrweb.ru/webhook/bugradar-triage
```

Секретов во фронтенде нет: доступ к модели остаётся внутри n8n.

## Настройка n8n

1. Импортируйте `n8n/bugradar_webhook.json`.
2. В ноде `Run Issue Classifier` выберите опубликованный sub-workflow `Практика 7.2 — Issue Classifier`.
3. Опубликуйте workflow.
4. Скопируйте Production URL ноды `BugRadar Webhook` в `.env`.

API возвращает:

```json
{
  "type": "bug",
  "confidence": 0.94,
  "priority": "Высокий",
  "summary": "Краткое резюме",
  "recommendation": "Следующий шаг"
}
```

## Тесты

```bash
npm test
npm run test:coverage
npm run build
```

MSW перехватывает запросы к webhook и подменяет ответы: успех, задержку, ошибку и пустой результат. Тесты проверяют:

- исходное пустое состояние и диалоги;
- обязательные поля и некорректный ввод;
- загрузку, успех, ошибку и повтор;
- полный путь от ввода до видимого результата;
- один запрос при двойном клике и повторном Enter во время ожидания;
- историю и её диалоги.

1. Открыть `docs/prototype.html` и сравнить его с приложением.
2. Показать `src/theme.ts` и компоненты Material UI.
3. Запустить n8n workflow, затем пройти основной сценарий в приложении.
4. Показать валидацию, загрузку, ошибку и защиту от повторной отправки.
5. Запустить `npm test` и показать MSW-обработчики в `src/test/handlers.ts`.
