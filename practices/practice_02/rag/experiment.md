# RAG

- Вход и цель
  - Вход: practices/practice_01/CASE.md, practices/practice_01/tests_integration.md, practices/practice_01/context.md, practices/practice_01/product_management.md, текущий practices/practice_01/adr.md (после R.C.T.F.).
  - Цель: проверить по разрешённым источникам, должен ли ADR фиксировать формат «контролируемого ответа» при REL-1 как соответствующий OUT-1, или это остаётся открытым вопросом.

## Разрешённые источники

| Файл или документ | Зачем нужен | Какой фрагмент используем |
|---|---|---|
| practices/practice_01/CASE.md | Нормативная формулировка правил | Определение REL-1/OUT-1/прочих правил; в REL-1 нет требований к формату контролируемого ответа |
| practices/practice_01/tests_integration.md | Интеграционные ожидания по REL-1 | «Нет 500; контролируемый ответ по REL‑1 | Код ответа и тело соответствуют договорённости (детали ответа — открытый вопрос)» |
| practices/practice_01/context.md | Context Pack для первого сценария | Формулировка REL-1 без конкретизации формата контролируемого ответа |
| practices/practice_01/product_management.md | Use case и ошибки/отказы | Фиксирует контролируемый ответ при таймауте LLM; показывает практику обозначать детали как «открытый вопрос» для ещё не согласованных аспектов |

## Реально использованный prompt

- Поисковая формулировка: «REL-1» И/ИЛИ «контролируемый ответ» И «формат» И/ИЛИ «открытый вопрос». Цель — найти явные указания на форму контролируемого ответа и проверить, зафиксировано ли соответствие OUT-1 where applicable.

## Наблюдаемый результат

- CASE.md: «REL-1: внешний LLM-вызов имеет timeout 10 секунд; ошибка превращается в контролируемый ответ.» Требования к формату контролируемого ответа отсутствуют.
- tests_integration.md: для кейса таймаута зафиксировано «Нет 500; контролируемый ответ по REL‑1», при этом прямо отмечено: «детали ответа — открытый вопрос».
- context.md: повторяет REL-1 без детализации формата контролируемого ответа.
- product_management.md: отражает подход — фиксировать факт контролируемого ответа и помечать неутверждённые детали как «открытый вопрос».

Вывод: В текущей базе знаний нет требования, чтобы контролируемый ответ строго соответствовал формату OUT‑1. Интеграционные проверки подчёркивают, что детали тела контролируемого ответа ещё открыты. Следовательно, формулировка ADR «формат контролируемого ответа соответствует OUT‑1» должна быть смягчена до статуса «открытого вопроса».
