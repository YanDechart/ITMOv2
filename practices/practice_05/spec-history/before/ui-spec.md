## User Scenarios & Testing *(mandatory)*

### User Story 1 - Посмотреть расписание на сегодня (Priority: P1)

Как студент, я открываю Mini My ITMO и хочу сразу увидеть своё имя, учебную группу и расписание на текущий день.

**Почему этот приоритет**: Это основной сценарий использования и минимальная ценность продукта — показать сегодня расписание с базовыми карточками.

**Independent Test**: При симуляции ответов логики (успех/пусто/ошибка) страница должна последовательно отобразить состояние загрузки, затем соответствующее состояние (список занятий, пустое состояние или ошибку с кнопкой «Повторить»).

**Acceptance Scenarios**:

1. Given страница открыта впервые и для «сегодня» есть занятия, When UI завершает загрузку, Then отображается имя студента и группа; Then выбран день «Сегодня»; Then показывается список карточек занятий, отсортированных по времени начала по возрастанию.
2. Given страница открыта впервые и для «сегодня» занятий нет, When UI завершает загрузку, Then отображается пустое состояние с ненавязчивым сообщением о том, что занятий нет.
3. Given страница открыта впервые и произошла ошибка получения расписания, When UI завершает загрузку, Then отображается состояние ошибки с понятным сообщением и кнопкой «Повторить», доступной с клавиатуры.
4. Given отображено состояние ошибки, When пользователь нажимает «Повторить», Then UI возвращается в состояние загрузки и при успехе показывает занятия или пустое состояние.

### User Story 2 - Переключение между днями недели (Priority: P2)

Как студент, я хочу переключаться между днями недели, чтобы посмотреть расписание на другой день.

**Почему этот приоритет**: После просмотра «сегодня», следующая потребность — быстро увидеть соседние дни недели.

**Independent Test**: При смене дня UI должен отобразить состояние загрузки и затем соответствующее состояние для выбранного дня; выбранный день визуально подсвечен; фокус корректно перемещается для доступности.

**Acceptance Scenarios**:

1. Given открыт «сегодня», When пользователь выбирает «Завтра», Then UI показывает индикатор загрузки и затем итоговое состояние (занятия/пусто/ошибка) для выбранного дня.
2. Given выбран «Понедельник», When пользователь с клавиатуры перемещается по контролу дней и выбирает «Среда», Then фокус и выделение обновляются, и контент соответствует «Среде».
3. Given пользователь в мобильном режиме, When он свайпает/прокручивает список дней, Then выбранный день обновляется и остаётся в пределах видимой области, без горизонтальной прокрутки страницы.

### User Story 3 - Просмотр карточек занятий (Priority: P3)

Как студент, я хочу видеть в карточке занятия название предмета, время, аудиторию и преподавателя, чтобы быстро понять, куда и когда идти.

**Почему этот приоритет**: Детализация занятий повышает полезность расписания и завершает минимальный набор информации.

**Independent Test**: Для каждого занятия отображаются четыре поля (название, время, аудитория, преподаватель) в единообразном формате; длинные названия не ломают верстку и корректно усечены визуально.

**Acceptance Scenarios**:

1. Given у занятия есть все поля, When UI рисует карточку, Then отображаются все четыре атрибута в читаемом виде.
2. Given отсутствует одно из полей (например, преподаватель), When UI рисует карточку, Then значение заменяется нейтральным символом «—» и карточка остаётся валидной визуально.

---

### Edge Cases

- Длинные названия предметов/ФИО/аудиторий (перенос/усечение без переполнения контейнеров).
- Пересекающиеся по времени занятия — порядок сортировки по времени начала сохраняется; визуально конфликты не решаются на этой версии.
- День без занятий (выходной/каникулы) — пустое состояние.
- Ошибки сети vs ошибка сервера — обе показываются как «ошибка получения расписания»; различия в сообщении зависят от классификации ошибок логики.
- Некорректные/частично пустые данные — UI использует дефолт «—» и не падает.
- Локализация времени: 24-часовой формат, локаль ru-RU; даты показываются человекочитаемо (например, «Пн, 2 ноя»).

## Requirements *(mandatory)*

### Структура экрана и элементы управления

- Header: имя студента и учебная группа.
- Контрол выбора дня недели: список дней (Пн–Вс) с подсветкой выбранного дня и маркировкой «Сегодня» при совпадении.
- Область контента расписания: список карточек занятий или состояния (loading/empty/error).
- Кнопка «Повторить» доступна в состоянии ошибки.

### Functional Requirements

- **FR-001**: UI MUST отображать имя студента и учебную группу в шапке.
- **FR-002**: UI MUST отображать контрол выбора дня недели с выбранным по умолчанию текущим днём («Сегодня»).
- **FR-003**: UI MUST при смене дня показывать индикатор загрузки до завершения получения данных.
- **FR-004**: UI MUST отображать карточки занятий с полями: название предмета, время (начало–конец), аудитория, преподаватель.
- **FR-005**: UI MUST сортировать занятия по времени начала по возрастанию.
- **FR-006**: UI MUST отображать пустое состояние, если для выбранного дня занятий нет (ненавязчивое сообщение).
- **FR-007**: UI MUST отображать состояние ошибки с сообщением и кнопкой «Повторить» при ошибке получения расписания.
- **FR-008**: UI MUST обеспечивать доступность: управление с клавиатуры (Tab/Enter/Space для выбора дня, Retry активируемая клавишей), корректный порядок фокуса, семантические роли и подписи.
- **FR-009**: UI MUST быть адаптивным: без горизонтальной прокрутки на телефонах; контрол дней компактен и прокручиваем, карточки стекаются вертикально.
- **FR-010**: UI MUST форматировать время в 24-часовом формате с ведущими нулями (например, 08:30–10:00), локализованно для ru-RU.
- **FR-011**: UI MUST сохранять выбранный день в пределах текущего сеанса просмотра (не сбрасывать при повторной загрузке данных/Retry).
- **FR-012**: UI MUST использовать нейтральный символ «—» для неизвестных/пустых значений в карточке (например, отсутствует преподаватель или аудитория).
- **FR-013**: UI MUST визуально различать активные элементы управления и их состояние (hover/focus/pressed/disabled) для доступности.

### Визуальные состояния UI

- Loading: видимый индикатор (скелетон/спиннер), недоступны элементы контента, доступно описание для скрин-ридера («Загрузка расписания…»).
- Success: список карточек; при отсутствии карточек — см. Empty.
- Empty: иллюстрация/иконка (опционально), краткое сообщение «На выбранный день занятий нет».
- Error: лаконичное сообщение, кнопка «Повторить», доступное объяснение для скрин-ридера («Не удалось загрузить расписание»).

### Доступность и адаптивность

- Клавиатурная навигация: все интерактивные элементы доступны и имеют видимый focus.
- Читаемость: межстрочные интервалы и контраст соответствуют базовым рекомендациям доступности; масштабирование текста до 200% не ломает лэйаут.
- Экранные читалки: элементы имеют понятные подписи (например, «Выбрать день: Понедельник (Сегодня)»; «Кнопка: Повторить загрузку»).
- Адаптивные брейкпоинты: телефон — одна колонка; планшет/десктоп — возможны две колонки карточек; контрол дней скроллируемый на маленьких экранах.

### Ожидания UI от логики (контракт)

- Данные профиля: имя студента (строка), учебная группа (строка). [NEEDS CLARIFICATION: источник и момент получения — вместе с расписанием или отдельным профилем?]
- Единица запроса расписания: по абсолютной дате (календарный день) или по неделе с последующим разделением по дням. [NEEDS CLARIFICATION: ключ запроса расписания — дата vs неделя]
- Ответ на запрос включает: список занятий для выбранного дня (может быть пустым); упорядочивание по времени начала на стороне логики желательно, но UI готов сортировать.
- Типы ошибок: предусмотреть различимые категории для корректных сообщений UI (например, сеть, сервер, доступ, неизвестная). [NEEDS CLARIFICATION: согласовать классификацию ошибок и отображаемые сообщения]
- Действия UI → логика: (1) первичная загрузка для выбранного дня; (2) повторная загрузка (Retry) для текущего выбранного дня; (3) загрузка при смене дня.

### Key Entities *(include if feature involves data)*

- **StudentProfile**: атрибуты — name, group.
- **ScheduleDay**: атрибуты — date (абсолютная дата), weekdayLabel (например, «Пн»), lessons[].
- **Lesson**: атрибуты — subject, startTime, endTime, room, teacher.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 95% пользователей видят индикатор загрузки в течение 0.3 секунды после открытия страницы.
- **SC-002**: 95% переключений дня завершаются отображением нового состояния (success/empty/error) менее чем за 1.5 секунды для пользователя.
- **SC-003**: 90% пользователей успешно находят и читают расписание на «сегодня» менее чем за 10 секунд без инструкций.
- **SC-004**: На мобильных устройствах отсутствует горизонтальная прокрутка при ширине экрана от 320px; все элементы управления помещаются в видимую область.
- **SC-005**: Все основные элементы управляются клавиатурой; 100% интерактивных элементов имеют видимый фокус и корректные текстовые подписи.
- **SC-006**: В 100% случаев на пустой день отображается понятное сообщение; в 100% ошибок отображается сообщение и кнопка «Повторить».

## Assumptions

- UI предназначен для студентов ИТМО, уже аутентифицированных и имеющих доступ к своим данным.
- «Сегодня» определяется по локальному времени пользователя.
- Формат времени — 24-часовой, локализация ru-RU.
- Кэширование и хранение данных вне скоупа; UI не несёт ответственности за долговременное хранение.
- В этой версии не предусматриваются сложные конфликты расписания, подсказки о маршрутах и т. п.
