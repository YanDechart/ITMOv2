# Mini My ITMO — демонстрация и доказательства

## Быстрый запуск

Из корня репозитория:

```bash
python3 -m http.server 8000 --directory practices/practice_05
```

Открыть: [http://localhost:8000/](http://localhost:8000/)

Автоматические тесты:

```bash
node --test practices/practice_05/tests/*.test.mjs
```

Требования к окружению: Python 3 и Node.js 18 или новее. Устанавливать зависимости не нужно.

## Сценарий демонстрации на 2–3 минуты

### 0:00–0:30 — стартовая страница

1. Открыть приложение.
2. Показать карточку студента, группу и переключатель Пн–Вс.
3. Обратить внимание, что текущий день отмечен как «Сегодня», а контент загружается из локального JSON.

### 0:30–1:15 — обычный и пустой день

1. Выбрать **Пн**.
2. Показать четыре карточки и порядок времени: `08:20`, `10:00`, `10:00`, `13:30`. В JSON занятия записаны не по порядку — сортировку выполняет logic service.
3. Выбрать **Вс**: вместо ошибки появляется корректное empty-состояние «На выбранный день занятий нет».

### 1:15–1:45 — необязательные поля

1. Выбрать **Ср**: у «Проектирования информационных систем» нет `room`, поэтому UI показывает `—`.
2. Выбрать **Пт**: у «Основ программной инженерии» нет `teacher`, UI также показывает `—`.

### 1:45–2:20 — ошибка и Retry

1. В DevTools временно заблокировать запрос `schedule.json` и перезагрузить страницу.
2. Показать error-состояние и доступную с клавиатуры кнопку «Повторить».
3. Снять блокировку и нажать «Повторить» — выполняется `retry()`, затем `getDay(currentDayId)`, и расписание возвращается.

Альтернатива без DevTools: этот сценарий автоматически проверяется stateful-загрузчиком в `schedule-controller.integration.test.mjs`.

### 2:20–2:50 — переключение и доступность

1. Быстро нажать Пн → Вт → Ср: должен остаться результат среды. Это политика latest-wins.
2. Переключить день клавишами Tab и Enter/Space, показать видимый focus.
3. При необходимости включить мобильный viewport 320 px: горизонтальной прокрутки нет.

## Визуальная проверка

В in-app browser фактически проверены и сняты три состояния реального приложения:

1. Понедельник с четырьмя отсортированными карточками.
2. Воскресенье с корректным empty-состоянием.
3. Мобильная среда с `—` вместо отсутствующей аудитории.

Среда выполнения показала эти снимки в чате, но не предоставила разрешённого файлового экспорта в каталог репозитория. Поэтому `evidence/` с искусственными или пересозданными изображениями не добавлялся. При сдаче эти же состояния воспроизводятся по сценарию выше напрямую в браузере.

## Итоги автоматических проверок

Финальный прогон: **26 тестов, 26 пройдено, 0 ошибок**.

Проверено:

- успешная загрузка Student и WeekSchedule;
- сортировка занятий по `startTime`, `endTime`, `subject`, `room`;
- пустой день без исключения;
- отсутствующие `room` и `teacher`;
- каталог ошибок и невалидные данные;
- ошибка загрузки и успешный Retry;
- защитные копии данных;
- latest-wins при обратном порядке завершения Promise;
- UI-controller с реальным logic service;
- выдача HTML, CSS, ES-модулей и JSON через локальный HTTP-сервер.
